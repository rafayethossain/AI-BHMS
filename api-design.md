## 1. API Standards

### 1.1 Base URL

```
Production:  https://api.bhms.com/api/v1
Staging:     https://api-staging.bhms.com/api/v1
Development: http://localhost:8000/api/v1
```

### 1.2 Versioning

| Strategy | Description |
|----------|-------------|
| URL-based | `/api/v1/...` (all app routers mount under `/api/v1/<app>/` in `config/urls.py`) |

### 1.3 Request Format

| Header | Value |
|--------|-------|
| Content-Type | application/json |
| Accept | application/json |
| Authorization | Bearer {token} (JWT via SimpleJWT) |
| X-Tenant-ID | {tenant_id} |

### 1.4 Response Format

DRF `ModelViewSet` routers return the resource JSON directly; list endpoints support
Django-filter pagination when enabled. Example shape:

```json
{
  "id": "uuid",
  "po_number": "PO-2026-001",
  "status": "open",
  "buyer": { "id": "uuid", "name": "…", "code": "…" },
  "quantity": 5000,
  "delivery_date": "2026-06-15",
  "created_at": "2026-01-15T10:30:00Z"
}
```

### 1.5 Filtering / Sorting / Search

`ModelViewSet`s use DRF defaults; queryset filters (`?status=…`, `?<fk>_id=…`) and
ordering are supported per viewset. Schema is auto-generated by drf-spectacular and
exposed under `/api/schema/`, `/api/docs/` (Swagger UI) and `/api/redoc/`.

## 3. Common Patterns

Routers register standard CRUD for each resource:

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/{resource}/` | List (optionally filtered/paginated) |
| POST | `/{resource}/` | Create (201) |
| GET | `/{resource}/{id}/` | Retrieve |
| PUT / PATCH | `/{resource}/{id}/` | Full / partial update |
| DELETE | `/{resource}/{id}/` | Delete (204) |

Nested/action endpoints are documented inline in §4 where they exist (e.g.
`purchase-orders/{po_pk}/hits`). Import endpoints (e.g. `setup/import/`) return a job
summary. All non-auth routes require `Authorization: Bearer {token}` and are
tenant-scoped.

## 5. Error Handling

### 5.1 Error Response Format

DRF returns error objects per viewset. Example:

```json
{
  "detail": "Validation errors",
  "errors": {
    "quantity": ["Quantity must be greater than 0"],
    "delivery_date": ["Delivery date must be in the future"]
  }
}
```

### 5.2 HTTP Status Codes

| Code | Description |
|------|-------------|
| 200 | OK - Success |
| 201 | Created - Resource created |
| 204 | No Content - Success (no body) |
| 400 | Bad Request - Invalid input |
| 401 | Unauthorized - Authentication required |
| 403 | Forbidden - Insufficient permissions |
| 404 | Not Found - Resource not found |
| 409 | Conflict - Resource conflict (e.g. unique violation) |
| 429 | Too Many Requests - Rate limit exceeded |
| 500 | Internal Server Error - Server error |

### 5.3 Error Codes

| Code | Description |
|------|-------------|
| VALIDATION_ERROR | Input validation failed |
| AUTHENTICATION_REQUIRED | Login required |
| INSUFFICIENT_PERMISSIONS | No access |
| RESOURCE_NOT_FOUND | Resource not found |
| DUPLICATE_RESOURCE | Resource already exists |
| BUSINESS_RULE_VIOLATION | Business rule violated |
| RATE_LIMIT_EXCEEDED | Too many requests |
| INTERNAL_ERROR | Server error |
